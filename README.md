# Enterprise Private GPT: поиск по техническим книгам

Учебный RAG-проект для ДЗ OTUS. Система ищет фрагменты в трёх технических книгах и отвечает на вопросы с указанием источников.

Вместо предложенного корпуса корпоративных документов я выбрал книги по генеративному ИИ, RAG и LangChain. После сдачи ДЗ эту базу можно расширять и использовать для поиска по собственной библиотеке.

**Текущий статус:** PDF загружаются, одна книга распознана через OCR, тексты разбиты на чанки и проиндексированы в локальной Chroma. Семантический поиск и ответы RAG проверены в консоли. Интерфейс и локальная LLM — следующие этапы.

## Как устроен проект

Обработка книг выполняется при подготовке базы; при вопросе пользователя повторно обрабатывать PDF не нужно.

- `src/config.py` — настройки из `.env`;
- `src/llm.py` — подключение к модели в Yandex AI Studio;
- `src/ingestion/pdf_loader.py` — чтение PDF и сохранённого результата OCR;
- `src/prepare_ocr.py` — однократное распознавание проблемной книги;
- `src/processing/chunker.py` — разбиение страниц на чанки;
- `src/storage/chroma_store.py` — доступ к локальной Chroma;
- `src/index_documents.py` — индексация всех книг;
- `src/search_chunks.py` — проверка базы и семантического поиска;
- `src/rag.py` — функция поиска и генерации ответа для будущего интерфейса;
- `src/rag_cli.py` — консольное сравнение ответов при `Top-K=3` и `Top-K=5`;
- `src/inspect_documents.py`, `src/inspect_chunks.py`, `src/check_embeddings.py`, `src/check_llm.py` — проверки отдельных этапов.

`src/storage/qdrant_store.py` оставлен для будущего сравнения с Qdrant; в текущем RAG используется Chroma. Разделение по этапам помогает понять, где возникла ошибка: при чтении PDF, распознавании, разбиении, поиске или генерации ответа.

## Корпус и подготовка текста

В корпус входят три книги:

1. «Генеративный ИИ на практике» (2026).
2. М. С. Девлин, «Построение LLM-агентов с помощью RAG, графов знаний и осмысления» (2026).
3. В. Дронов, «Искусственный интеллект с LangChain» (2026).

PDF лежат локально в `data/raw/private/` и не публикуются в репозитории.

Сначала текст извлекался через PyMuPDF. У книги «Генеративный ИИ на практике» текстовый слой оказался неполным: видимые русские абзацы пропадали при извлечении. Поэтому эту книгу распознали через Tesseract (`rus+eng`). Результат хранится в `data/processed/private/generative_ai_ocr.jsonl`, по одной странице в строке. Повторное чтение книги не требует нового запуска OCR. Две остальные книги читаются напрямую из PDF.

Каждая непустая страница становится `LangChain Document` с названием файла (`source`) и номером **PDF-страницы** (`page`). Этот номер может отличаться от номера, напечатанного в книге: обложка и вступительные страницы тоже учитываются. Порог 80 символов нужен для диагностики страниц с малым количеством текста; автоматически такие страницы не удаляются.

После подготовки получено **961 непустая страница из 987 страниц PDF** и **1 989 801 символ**. OCR восстановил основной текст первой книги, но иногда ошибается в коде и латинских символах. Поэтому примеры кода в ответах следует сверять с указанной страницей оригинального PDF.

## Чанкирование и векторная база

Страницы разбиваются через LangChain `RecursiveCharacterTextSplitter`: `chunk_size=1000` символов, `chunk_overlap=150` символов. Сплиттер старается сохранять границы абзацев и строк; если фрагмент слишком длинный, использует более мелкие разделители.

Получено **2850 чанков**: 1070 из первой книги, 599 из книги Девлин и 1181 из книги Дронова. Каждый чанк сохраняет источник, PDF-страницу, номер внутри страницы, параметры разбиения и `chunk_id`. В ID входят источник, параметры разбиения, страница и номер чанка. Размер чанка — первая рабочая конфигурация для этого корпуса, а не универсальный оптимум.

Для эмбеддингов используется локальная мультиязычная модель `BAAI/bge-m3`. Она создаёт векторы размерности 1024. Чанки и их метаданные сохраняются в локальной Chroma (`data/chroma/`). После индексации в базе проверено **2850 записей**. Модель эмбеддингов загружается в общий кеш Hugging Face, а не хранится в Git-репозитории.

## Ответ на вопрос

При запросе BGE-M3 векторизует вопрос, Chroma находит наиболее близкие чанки, а промпт передаёт их языковой модели. Промпт требует отвечать по найденным фрагментам, указывать их номера и сообщать, если ответа нет. `src/rag.py` возвращает ответ и найденные документы; `src/rag_cli.py` отдельно сравнивает `Top-K=3` и `Top-K=5` и измеряет время поиска и генерации.

Проверены модели YandexGPT 5.1 и Qwen через Yandex AI Studio. Модель выбирается переменной `YC_MODEL_ID` в `.env`; для опытов с Qwen использовалась `qwen3.6-35b-a3b`.

**Подробные вопросы, ответы, замеры и ограничения:** [docs/evaluation.md](docs/evaluation.md).

## Установка и запуск

Нужны Python 3.12, `uv`, три PDF корпуса и Tesseract с языками `rus` и `eng` для подготовки OCR. Из корня проекта:

```bash
uv sync
cp .env.example .env
mkdir -p data/raw/private
```

В `.env` укажите свои `YC_API_KEY`, `YC_FOLDER_ID` и нужный `YC_MODEL_ID`. Поместите PDF в `data/raw/private/`. При первой подготовке выполните команды по порядку:

```bash
uv run python -m src.check_llm
uv run python -m src.prepare_ocr
uv run python -m src.inspect_documents
uv run python -m src.inspect_chunks
uv run python -m src.check_embeddings
uv run python -m src.index_documents
uv run python -m src.search_chunks
```

После индексации для вопроса и сравнения двух значений `Top-K`:

```bash
uv run python -m src.rag_cli
```

`index_documents` при повторном запуске использует стабильные ID чанков. Для обычного вопроса повторять индексацию не требуется.

## Приватность и ограничения

`.env`, PDF, результат OCR, Chroma и виртуальное окружение исключены из Git. BGE-M3 и векторная база работают локально.

**Текущая система не полностью приватная:** вопрос и найденные фрагменты отправляются в Yandex AI Studio для генерации ответа. До проверки локальной LLM нельзя утверждать, что система работает без интернета или обеспечивает полную изоляцию документов. Этот пункт ДЗ остаётся открытым. 
Другие ограничения: OCR может искажать код; поиск иногда выбирает близкую по теме, но неподходящую страницу; даже при наличии источников модель может неверно пересказать фрагмент. Интерфейс, его скриншоты и проверка локальной модели будут добавлены после реализации.
