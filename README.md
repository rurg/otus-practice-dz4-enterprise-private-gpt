# Enterprise Private GPT: поиск по техническим книгам

Учебный проект по сборке RAG-системы для поиска и ответов по собственному корпусу технической литературы. Работа выполняется в рамках ДЗ OTUS «Enterprise Private GPT».

Вместо предложенного примера корпоративных документов выбран корпус из трёх книг по генеративному ИИ, RAG и LangChain. Такой корпус полезен и после сдачи задания: его можно расширять новыми книгами и использовать для поиска нужных объяснений с указанием источника и страницы.

**Текущий статус:** проверено подключение к YandexGPT, реализованы загрузка PDF, OCR одной книги и чанкирование. Эмбеддинги, векторная база, RAG-ответы и интерфейс пока не реализованы.

## Почему проект разделён на модули

Обработка документа и ответ на вопрос — разные этапы. Поэтому код разделён по задачам:

- `src/config.py` — настройки и переменные окружения;
- `src/llm.py`, `src/check_llm.py` — подключение к YandexGPT и проверочный запрос;
- `src/ingestion/pdf_loader.py` — загрузка страниц PDF;
- `src/prepare_ocr.py` — однократное распознавание книги с проблемным текстовым слоем;
- `src/processing/chunker.py` — разбиение страниц на фрагменты;
- `src/inspect_documents.py`, `src/inspect_chunks.py` — проверка результата на реальных книгах;
- `src/storage/` — место для следующего этапа с векторными базами. Файлы `chroma_store.py` и `qdrant_store.py` пока пустые.

Это позволяет проверять извлечение текста и чанкирование до создания векторов и вызовов LLM. Если поиск впоследствии окажется плохим, можно будет отдельно проверить, на каком этапе потерялась информация.

## Корпус и подготовка данных

В корпус входят:

1. «Генеративный ИИ на практике» (2026).
2. М. С. Девлин, «Построение LLM-агентов с помощью RAG, графов знаний и осмысления» (2026).
3. В. Дронов, «Искусственный интеллект с LangChain. Профессиональное…» (2026).

PDF хранятся локально в `data/raw/private/` и не публикуются в репозитории.

Сначала для извлечения текста использовался PyMuPDF. Каждая непустая страница превращается в `LangChain Document` с метаданными `source` (имя файла) и `page` (номер страницы). Нумерация начинается с 1, чтобы найденное место можно было открыть в книге. Порог 80 символов используется **для диагностики** страниц с малым количеством текста; короткие страницы автоматически не удаляются.

Проверка показала, что у книги «Генеративный ИИ на практике» текстовый слой неполный: часть русских абзацев отсутствовала, хотя на странице они видны. Поэтому эта книга распознана целиком через Tesseract с языками `rus+eng`. Результат сохраняется в `data/processed/private/generative_ai_ocr.jsonl`: одна строка содержит номер и текст одной страницы. При последующих запусках загрузчик читает готовый результат и не запускает OCR повторно.

Другие две книги читаются непосредственно из PDF. Для них PyMuPDF извлекает текст с `sort=True`, чтобы приблизить порядок фрагментов к порядку чтения страницы.

**Ограничение OCR:** основной текст восстановлен, но отдельные фрагменты кода, латинские символы и подписи распознаются с ошибками. Например, `float16` может превратиться в похожее, но неверное написание. Автоматически «исправлять» такие места без сверки с оригиналом мы не стали: это могло бы добавить новые ошибки. При ответе по коду нужно проверять указанную страницу PDF.

После OCR проверка корпуса показала: **987 страниц PDF, 961 непустая текстовая страница, 1 989 801 извлечённый символ**.

## Чанкирование

Используется `RecursiveCharacterTextSplitter` из LangChain:

- `chunk_size = 1000` символов;
- `chunk_overlap = 150` символов;
- сначала проверяются границы абзацев и строк, затем знаки препинания, пробелы и, при необходимости, отдельные символы.

Это исходная рабочая конфигурация для технических книг, а не утверждение об универсально оптимальном размере. Фрагменты наследуют название файла и номер страницы. Дополнительно записываются номер чанка на странице, `chunk_id` и параметры стратегии. `chunk_id` включает источник, страницу, номер чанка и параметры разбиения.

Получено **2850 чанков**: 1070 из первой книги, 599 из книги Девлин и 1181 из книги Дронова. Скрипт проверки выводит распределение длин и два первых чанка страницы 25 каждой книги. Короткие чанки пока сохранены: среди них встречаются заголовки и номера страниц. Их влияние на качество поиска проверим после создания базы.

## Модель и границы приватности

Для первого этапа генерации используется **YandexGPT Pro 5.1** через API Yandex AI Studio. Подключение проверено отдельным консольным запросом. Настройки читаются из локального `.env`; в Git находится только `.env.example` без ключей.

Исходные PDF, результат OCR, локальная векторная база, `.env` и виртуальное окружение исключены через `.gitignore`. При этом система с облачной LLM **не обеспечивает полной изоляции данных**: после сборки RAG найденные фрагменты будут отправляться в Yandex AI Studio для генерации ответа. Локальную LLM планируется проверить отдельным этапом.

## Как повторить текущий этап

Нужны Python 3.12, `uv`, три PDF-файла корпуса и Tesseract с языками `rus` и `eng` для OCR первой книги.

~~~bash
uv sync
cp .env.example .env
mkdir -p data/raw/private

Укажите свои `YC_API_KEY` и `YC_FOLDER_ID` в `.env`, затем поместите PDF в `data/raw/private/`.

```bash
uv run python -m src.check_llm
uv run python -m src.prepare_ocr
uv run python -m src.inspect_documents
uv run python -m src.inspect_chunks
