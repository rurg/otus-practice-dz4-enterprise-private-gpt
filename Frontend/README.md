# Веб-интерфейс 2PeachGPT (не без помощи GLM5.2)



Папка `Frontend/` содержит интерфейс на Next.js. Он даёт возможность задавать вопросы по трём книгам, просматривать найденные фрагменты с PDF-страницами и менять параметры RAG без правки Python-кода. Основное описание учебного проекта и соответствия ДЗ — в [корневом README](../README.md), результаты испытаний — в [evaluation.md](../docs/evaluation.md).

## Запуск с реальной базой

Сначала подготовьте корпус и Chroma по инструкции в корневом README. В отдельном терминале **из корня репозитория** запустите Python API:

```bash
uv run uvicorn rag_server:app --port 8000 --reload
```

Создайте `Frontend/.env.local` с одной строкой:

```dotenv
RAG_BACKEND_URL=http://127.0.0.1:8000
```

В другом терминале запустите фронт:

```bash
cd Frontend
npm ci
npm run dev
```

Откройте `http://localhost:3000`. После первоначальной установки для следующих запусков достаточно `npm run dev`. Если изменили `.env.local`, перезапустите Next.js. Оба терминала должны оставаться запущенными. `Frontend/.env.local` игнорируется Git; ключи Yandex AI Studio находятся в корневом `.env`, который читает Python.

## Что видно в интерфейсе

- Состояние подключения, число книг, страниц и чанков, выбранные LLM, модель эмбеддингов и векторная база. В реальном режиме эти числа приходят из Chroma через Python API.
- Список диалогов слева: кнопка «Новый диалог», переключение между чатами, переименование и удаление. Новые вопросы добавляются в текущий диалог.
- Ответ в центре, а справа — найденные фрагменты, книга, номер PDF-страницы и порядок выдачи. Если метрика Chroma не подтверждена как cosine, процент похожести не показывается.
- Вкладка «Параметры»: Top-K от 1 до 10, temperature, время поиска и генерации, токены при наличии данных от API, описание промпта и этапов RAG.
- Подсказки для трёх типов испытаний: по корпусу, вне корпуса и конфликтный вопрос. Это готовые формулировки вопросов, а не автоматическая оценка качества ответа.

Диалоги и ответы сохраняются [Zustand persist](src/store/chat-store.ts) в `localStorage` текущего браузера. Они остаются после обновления страницы, но не синхронизируются между устройствами и могут исчезнуть при очистке данных сайта. История показывается пользователю, **но пока не передаётся LLM как контекст разговора**: сервер отвечает на каждый текущий вопрос отдельно.

## Как запрос проходит через приложение

Страница вызывает [маршруты Next.js](src/app/api/rag/): `/api/rag/status`, `/api/rag/documents` и `/api/rag/chat`. При заданном `RAG_BACKEND_URL` они обращаются соответственно к `/status`, `/documents` и `/chat` в корневом [rag_server.py](../rag_server.py). Python-сервер открывает Chroma, векторизует вопрос локальной BGE-M3, ищет Top-K чанков, собирает промпт и вызывает модель через Yandex AI Studio.

Ответ передаётся как SSE-события: категория, источники, части текста, метрики и завершение. Python сначала получает **полный** ответ `llm.invoke()`, затем отправляет его частями; потоковой генерации самой модели здесь нет. Если реальный бэкенд недоступен, интерфейс показывает ошибку. Если `RAG_BACKEND_URL` вообще не задан, маршруты используют встроенный [демонстрационный движок](src/lib/rag/mock-engine.ts) с примерными данными. Демонстрационный режим не следует использовать для результатов ДЗ.
